# ACCESSIBILITY — মান, পদ্ধতি ও সীমা

## ১. লক্ষ্য

অ্যাপটি বাংলা-ভাষী ব্যবহারকারীর জন্য, তাই ভাষা/লিপি-সংক্রান্ত অ্যাক্সেসিবিলিটি এখানে
সাধারণ ওয়েব অ্যাপের চেয়ে বেশি জরুরি। লক্ষ্য: **কীবোর্ড-প্রথম**, স্ক্রিন-রিডারে অর্থপূর্ণ,
বাংলা ফন্ট লোড না হলেও ব্যবহারযোগ্য।

## ২. বাস্তবায়িত মান

| বিষয় | কী করা হয়েছে |
|---|---|
| ভাষা | `<html lang="bn">` — স্ক্রিন-রিডার বাংলা উচ্চারণ ব্যবহার করবে |
| পেজ কাঠামো | header → main → section(card) → footer; প্রতিটি section-এ `aria-labelledby` |
| Headings | ঠিক একটি `h1`; প্রতিটি card-এ `h2`; ক্রম ভাঙা নয় |
| Skip link | প্রথম Tab-এ “মূল অংশে যান” লিংক দৃশ্যমান হয় |
| ইনপুট label | দৃশ্যমান `<label for="amount">`, plus `aria-describedby="amount-help"` |
| ত্রুটি | `role="alert"` (তাত্ক্ষণিক ঘোষণা) + `aria-invalid="true"` + দৃশ্যমান লাল বর্ডার ও **লেখা** |
| ফলাফল | `<output for="amount">` — DOM-এ সত্যিকারের text node, তাই কপি/সিলেক্ট/পড়া যায় |
| Live region | ফলাফল ও ত্রুটি `aria-live="polite"` অঞ্চলেও যুক্ত হয় (মাঝপথে নয়, সম্পূর্ণ বাক্য) |
| রঙ | কোনো তথ্য শুধু রঙে নয় — “পরীক্ষামূলক” ট্যাগে লেখাও আছে; ত্রুটিতে লেখা আছে |
| Focus | সব ইন্টারঅ্যাকটিভ উপাদানে দৃশ্যমান `:focus-visible` outline (৩px, অফসেট ২px) |
| কীবোর্ড | Tab ক্রম স্বাভাবিক; রেডিও গ্রুপে তীর-কী; Escape ইনপুট খালি করে; `Enter` বাটনে কাজ করে |
| Touch target | বাটন ≥ ৪৪px উচ্চতা, checkbox/radio ≥ ১৮px, মোবাইলে বড় ফন্ট |
| Reduce motion | `prefers-reduced-motion: reduce`-এ সব transition/animation নিষ্ক্রিয় |
| Dark mode | `prefers-color-scheme: dark`-এ পূর্ণ থিম; contrast যাচাইকৃত |
| Zoom/রিফ্লো | ৩২০px প্রস্থ পর্যন্ত ভাঙে না; ২০০% জুমে অনুভূমিক স্ক্রল ছাড়া পড়া যায় |
| ফন্ট fallback | Noto Sans Bengali → Hind Siliguri → SolaimanLipi → Nikosh → system-ui |
| রূপকথা নয় | “সম্পূর্ণ অ্যাক্সেসিবল” দাবি করা হয় না; নিচের সীমাগুলো স্বীকৃত |

## ৩. স্বয়ংক্রিয় পরীক্ষা (CI-তে চলে)

`tests/e2e/accessibility.spec.ts`, Chromium (headless), axe-core:

1. **আলো/ডার্ক ডিফল্ট অবস্থায়** — no serious/critical violation।
2. **ফলাফল দেখানো অবস্থায়** এবং **ত্রুটি দেখানো অবস্থায়** — একই শর্ত।
3. **কীবোর্ড-only যাত্রা** — Tab দিয়ে skip link → ইনপুট → টাইপ → রীতি পরিবর্তন → কপি বাটন → Enter।
4. **ঘোষণা** — `aria-describedby` ও `role="alert"` যাচাই।
5. **টেক্সট হিসেবে ফলাফল** — DOM Range দিয়ে সিলেক্ট করে হুবহু বাক্য পাওয়া যায়।

স্ক্রিপ্টে করার কারণ: হাতে করা পরীক্ষা ভুলে যাওয়া যায়, আর PR-এ সেটি প্রমাণ থাকে।

## ৪. যা স্বয়ংক্রিয়ভাবে **হয় না**

| ফাঁক | কেন গুরুত্বপূর্ণ | পরিকল্পনা |
|---|---|---|
| আসল স্ক্রিন-রিডার (NVDA, TalkBack, VoiceOver) | বাংলা উচ্চারণ ও সংখ্যা পড়ার আচরণ যন্ত্রে ফারাক হয় | release-এর আগে হাতে পরীক্ষা: `docs/RELEASE_CHECKLIST.md` |
| Android Chrome / iOS Safari | মোবাইল ওয়েব বাংলা কীবোর্ড, কপি-পেস্ট, ফন্ট রেন্ডারিং | হাতে smoke test বাকি |
| ২০০% জুমে বাংলা যুক্তাক্ষরের রেন্ডারিং | ফন্ট-নির্ভর, ইঞ্জিন-মাপা যায় না | হাতে |
| Reduce-motion + স্ক্রল অ্যানিমেশন | অ্যাপে অ্যানিমেশন নেই, তাই ঝুঁকি কম | — |
| ডিসলেক্সিয়া/সহজ-ভাষা | সহজ বাংলা লেখা হয়েছে, কিন্তু ব্যবহারকারী-পরীক্ষা হয়নি | ভবিষ্যতের কাজ |

“axe pass করেছে” মানে “অ্যাক্সেসিবল” নয় — এই নথি সেটিই স্পষ্ট করে।

## ৫. নতুন UI যোগ করলে করণীয়

1. সেমান্টিক HTML আগে (button/label/table/output), ARIA পরে।
2. কীবোর্ড-শুধু ব্যবহার করে দেখুন: মাউস ছুঁবেন না।
3. `textContent` ব্যবহার করুন, `innerHTML` নয় (XSS ও স্ক্রিন-রিডার দুই দিক থেকেই নিরাপদ)।
4. রঙ ছাড়া অন্য সংকেত রাখুন (লেখা/আইকন/প্যাটার্ন)।
5. `npm run test:e2e` চালান — axe-এর serious/critical violation থাকলে build fail করবে।
