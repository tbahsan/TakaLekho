# কথায় লেখার নিয়ম (RULES)

> এই নথিটি `src/data/numwords.bn.json` ও `src/engine/convert.ts`-এর আচরণ ব্যাখ্যা করে।
> কোড আর এই নথির অমিল হলে bugs — এবং সেটি CI (`npm test` + `npm run validate:data`) ধরবে।

## ১. গোষ্ঠী-বিন্যাস (দেশীয় রীতি)

অঙ্কটি ডানে থেকে ভাগ হয়: শেষ তিন অঙ্ক, তার আগে দুই-দুই অঙ্ক।

```text
1,23,45,678
└┬┘└┬┘└┬┘└──┘
 │  │  │   └── একক (678)
 │  │  └────── হাজার (45)
 │  └───────── লাখ (23)
 └──────────── কোটি (1)
```

`৯৯,৯৯,৯৯,৯৯৯` = ৯ কোটি ৯৯ লাখ ৯৯ হাজার ৯৯৯। ভেতরের হিসাব: কোটি = ১০⁷, লাখ = ১০⁵,
হাজার = ১০³, শতক = ১০²।

## ২. রূপান্তরের ধাপ (এই ক্রমে, কোনো ধাপ বাদ নেই)

1. `trim()` — কেবল বাইরের ফাঁকা বাদ।
2. ঐচ্ছিক `৳` সরানো (শুধু প্রথম অক্ষর হলে)।
3. অক্ষর-যাচাই: অঙ্ক / কমা / বিন্দু ছাড়া কিছু থাকলে ত্রুটি।
4. অঙ্ক-লিপি যাচাই: বাংলা অথবা ইংরেজি, দুটো একসঙ্গে নয়।
5. বাংলা অঙ্ক → ইংরেজি অঙ্ক (শুধু রূপান্তরের সুবিধার্থে, মান বদলায় না)।
6. দশমিক ও কমা বিশ্লেষণ → `integerPart`, `fractionPart` (string আকারে)।
7. গোষ্ঠী ভাঙা → কোটি / লাখ / হাজার / শতক / একক।
8. ০–৯৯ তালিকা থেকে শব্দ, শূন্য গোষ্ঠী বাদ।
9. শতক-শব্দে রীতি-ভিত্তিক suffix যোগ (`শত` / `শ`)।
10. বাক্য তৈরি: `তাকা শব্দ … টাকা [পয়সা শব্দ … পয়সা] [মাত্র]`।

**কোথাও `Number` বা `parseFloat` নয়** — সম্পূর্ণ পথে অঙ্ক string হিসেবেই থাকে,
তাই পয়সার মান কখনো রাউন্ড হয় না।

## ৩. শব্দ-তালিকা (০–৯৯)

তালিকা সম্পূর্ণ repository-র ভেতরে লেখা; কোনো অনুমোদিত-বহির্ভূত অভিধান থেকে কপি করা হয়নি।
প্রতিটি এন্ট্রির বানান `docs/TABLE.md`-এ পর্যালোচনার জন্য ছাপা হয়।

বিশেষ খেয়াল:

- **১৪ = “চৌদ্দ”** (কথ্য “চোদ্দ” নয়) — বিকল্পটি `knownVariants`-এ আছে, কোনো রীতি ব্যবহার করে না।
- **১৬ = “ষোলো”**, **১৮ = “আঠারো”**।
- ২০২৪-পরবর্তী অভিধান-ভিত্তিক রূপ `ঊনত্রিশ` ইত্যাদি দিয়ে ঊন-সংখ্যাগুলো লেখা হয়েছে (যেমন ২৯, ৩৯, ৪৯ … ৯৯)।
- একই শব্দ দুটি সংখ্যার জন্য ব্যবহৃত হয় না — `tests/unit/unicode-hygiene.test.ts` সেটি যাচাই করে।

## ৪. শতক

| ইনপুট | ডিফল্ট (দাপ্তরিক) | পরীক্ষামূলক (কথ্য) |
|---|---|---|
| 100 | একশত | একশ |
| 200 | দুইশত | দুইশ |
| 900 | নয়শত | নয়শ |
| 1100 | এক হাজার একশত | এক হাজার একশ |
| 11100 | এগারো হাজার একশত | এগারো হাজার একশ |
| 100100 | এক লাখ একশত | এক লাখ একশ |

`এগারোশ`-এর মতো সংকুচিত রূপ ইচ্ছাকৃতভাবে **দেওয়া হয় না**, কারণ সেখানে দুইটি ভিন্ন
বিশ্লেষণ সম্ভব (“এগারোশ” = 1100, অথবা “এক হাজার একশ”)। স্পষ্ট রূপই নিরাপদ।

## ৫. পয়সা

- দুই ঘর না লিখলেও মান ঠিক থাকে: `12.5` = ৫০ পয়সা।
- পয়সা ০ হলে অংশটি বাদ: `12.00` → “বারো টাকা মাত্র”।
- পয়সা ১–৯ হলে শূন্য লেখা হয় না: `12.05` → “পাঁচ পয়সা”।
- টাকা ০ কিন্তু পয়সা থাকলে টাকার শব্দ থাকে: `0.01` → “শূন্য টাকা এক পয়সা মাত্র”।

## ৬. “মাত্র” ও যোজক

- ডিফল্ট রীতিতে বাক্যের শেষে একবার `মাত্র`; ফিক্সচারে সেটি যাচাই করা হয়
  (উদাহরণে ঠিক একটি `মাত্র` থাকতে হবে — `scripts/validate-data.mjs`)।
- সংখ্যার গোষ্ঠীর মাঝে কখনো `ও` বসে না: “বারো হাজার চারশত পঞ্চাশ”, “বারো হাজার ও চারশত পঞ্চাশ” নয়।

## ৭. নতুন রীতি বা নতুন শব্দ যোগ করার প্রক্রিয়া

1. `src/data/numwords.bn.json` বদলান (তালিকা) বা `variants`-এ নতুন entry যোগ করুন।
2. `tests/fixtures/golden.json`-এ expected output লিখুন (ইঞ্জিন চালিয়ে নয় — ভাষা জেনে)।
3. `node scripts/build-table.mjs` চালিয়ে পর্যালোচনা-পত্র (`docs/TABLE.md`, `docs/TABLE.csv`) নতুন করে বানান।
4. `npm test` ও `npm run validate:data` চালান।
5. রীতির `reviewStatus` পরিবর্তন করুন এবং PR-এ কারণ লিখুন। কোনো রীতিকে `reviewed` বলতে হলে
   `docs/EVALUATION.md`-এ পর্যালোচনার রেকর্ড থাকতে হবে।
